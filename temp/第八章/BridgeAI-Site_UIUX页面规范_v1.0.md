# BridgeAI-Site UI/UX 页面规范 v1.0

> **产品名称：** BridgeAI-Site 智慧工地 AI Agent 平台  
> **文档类型：** UI/UX 页面规范  
> **适用阶段：** 第一阶段 MVP  
> **编制单位：** 浙江悟联信息科技有限公司  
> **编制人：** 周仙通  
> **版本：** v1.0  
> **设计基调：** 深色科技感、工程驾驶舱、信息高密度、风险优先、操作可追踪

---

# 1. 文档目的

本规范用于统一 BridgeAI-Site 第一阶段 MVP 的页面结构、视觉语言、交互方式、组件行为、状态反馈和响应式适配要求。

本规范是以下工作的直接依据：

1. Figma 高保真设计；
2. 前端组件开发；
3. 页面验收；
4. 交互测试；
5. 多端适配；
6. 客户演示；
7. 后续设计系统建设。

---

# 2. 设计原则

## 2.1 风险优先

页面应优先展示高风险事件、未处理告警、逾期整改、离线摄像头、推理异常和重点区域。装饰性信息不得压过风险信息。

## 2.2 工程优先

设计应符合工程管理人员的使用习惯：信息清晰、操作路径短、状态明确、数据可追踪、异常可定位、结果可导出。

## 2.3 高信息密度

BridgeAI-Site 面向项目经理、安全员、监理和运维人员，页面应允许用户在同一工作区内完成判断。避免大面积空白、过度卡片化、过度动画和过深层级。

## 2.4 一致性

风险颜色、状态标签、按钮层级、表单布局、列表筛选、抽屉、弹窗、详情页面、空状态和错误状态必须保持统一。

## 2.5 可追踪

所有影响业务状态的操作都应记录操作人、时间、修改前状态、修改后状态、操作说明和关联证据。

# 3. 设计系统

## 3.1 视觉主题

第一阶段采用深色科技主题，整体应体现工程感、安全感、稳定感、数据感和可信赖感。页面背景使用深色层级，不建议使用纯黑。

| 层级 | 用途 |
|---|---|
| Background 1 | 全局页面背景 |
| Background 2 | 主内容容器 |
| Background 3 | 卡片、表格、侧栏 |
| Background 4 | 悬浮、弹窗、抽屉 |
| Border | 分割线、输入框边框 |

## 3.2 色彩语义

### 风险等级

| 风险等级 | 语义 | 使用场景 |
|---|---|---|
| 一级 | 重大风险 | 明火、核心危险区入侵 |
| 二级 | 较大风险 | 高处作业违规 |
| 三级 | 一般风险 | 未戴安全帽 |
| 四级 | 提示风险 | 人员聚集、车辆停留 |

### 状态语义

- 正常：绿色；
- 警告：橙色；
- 错误：红色；
- 信息：蓝色；
- 禁用：灰色；
- 处理中：蓝紫或动态指示；
- 已完成：绿色；
- 已忽略：中性灰。

所有颜色必须同时配合文字或图标，不能只依赖颜色表达。

## 3.3 字体层级

| 级别 | 用途 |
|---|---|
| Display | 驾驶舱大标题 |
| H1 | 页面标题 |
| H2 | 模块标题 |
| H3 | 卡片标题 |
| Body | 正文、表格 |
| Caption | 辅助说明、时间 |
| Number | KPI 数值 |

数字建议使用等宽数字样式，减少数据刷新时的视觉跳动。

## 3.4 间距体系

统一使用 4px 基础单位：

```text
4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48
```

常用规则：卡片内边距 16 或 20px，页面左右边距 24px，表单字段间距 16px，区块间距 24px，弹窗内边距 24px。

## 3.5 圆角与阴影

- 普通卡片：6～8px；
- 输入框：4～6px；
- 弹窗：8～12px；
- 视频窗口：4px；
- 标签：4px；
- 阴影轻量，避免过度发光。

# 4. 全局布局规范

## 4.1 桌面端主框架

```text
┌─────────────────────────────────────────────┐
│ 顶部栏：Logo / 项目切换 / 消息 / 用户        │
├──────────┬──────────────────────────────────┤
│ 左侧导航 │ 页面标题 / 面包屑 / 页面操作区     │
│          ├──────────────────────────────────┤
│          │ 主内容区                          │
└──────────┴──────────────────────────────────┘
```

顶部栏包含 Logo、产品名称、当前项目、项目切换、全局搜索、告警消息、系统通知、用户头像和退出登录。

左侧一级菜单：

- 首页驾驶舱；
- GIS 一张图；
- 视频监控；
- AI 中心；
- 告警中心；
- 整改中心；
- 设备管理；
- 报表中心；
- Agent 助手；
- 系统管理。

## 4.2 内容区结构

统一采用：页面标题区、筛选区、内容区、分页区。页面标题区包含标题、面包屑、说明文字和页面级操作按钮。

## 4.3 页面宽度

- 驾驶舱、GIS、视频墙：全宽；
- 常规管理页：流式全宽；
- 表单页：最大宽度建议 1200px；
- 详情页：左右双栏或右侧抽屉。

---

# 5. 全局组件规范

## 5.1 按钮

按钮分为主要、次要、文本、危险和图标按钮。同一区域只允许一个主要按钮。删除、关闭、驳回使用危险语义。纯图标按钮必须有 Tooltip。异步操作显示 Loading 并防止重复提交。

## 5.2 表格

表格应支持固定表头、列宽配置、列显示隐藏、排序、筛选、多选、批量操作、导出、分页、空状态、加载状态和错误状态。

## 5.3 表单

表单统一使用左标签右输入、必填标记、实时校验、提交前完整校验和贴近字段的错误信息。复杂表单按基本信息、业务配置、高级配置、权限配置和审计信息分区。

## 5.4 弹窗与抽屉

弹窗用于确认操作、简单新增、简短说明和危险操作确认。抽屉用于事件详情、摄像头详情、工单详情、模型详情和复杂编辑。

## 5.5 通知反馈

- 成功：Toast；
- 轻微错误：Toast；
- 严重错误：Alert；
- 长任务：进度条；
- 后台任务：消息中心；
- 不可逆操作：确认弹窗。

---

# 6. 登录页规范

页面采用左侧品牌区、右侧登录表单。左侧展示 Logo、产品名称、产品定位、智慧工地背景和公司名称。右侧包含用户名、密码、验证码、记住登录状态、登录按钮、忘记密码和版本号。

状态包括：默认、输入中、校验错误、登录中、登录失败、账号锁定、Token 过期。

---

# 7. 首页驾驶舱规范

用户应在 10 秒内知道：今天是否安全、哪里风险最高、哪些问题未解决、哪些设备异常、是否需要立即行动。

推荐布局：

```text
┌──────────────────────────────────────────────┐
│ 项目名称 / 日期 / 全屏 / 刷新                 │
├────────┬────────┬────────┬────────┬─────────┤
│ 今日告警│ 高风险 │ 待整改 │ 逾期数 │ 在线率   │
├──────────────────────┬───────────────────────┤
│ GIS 风险地图          │ 告警趋势              │
├──────────────────────┼───────────────────────┤
│ 实时视频轮播          │ 风险类型分布           │
├──────────────────────┼───────────────────────┤
│ 最新告警              │ 班组/区域风险排名      │
└──────────────────────┴───────────────────────┘
```

KPI 卡片必须包含指标名称、当前值、趋势、风险提示和跳转入口。图表必须包含标题、时间范围、单位、图例、Tooltip、空数据状态和更新时间。

---

# 8. GIS 一张图规范

页面采用顶部工具栏、左侧图层树、中央地图主视图和右侧详情抽屉。

图层包括项目边界、施工区域、危险区域、摄像头、告警、设备、人员、车辆和无人机。支持图层开关、数量、状态筛选、搜索和聚合显示。

摄像头点位状态：在线、离线、告警中、维护中、AI 运行中、AI 异常。点击点位打开预览卡片，显示名称、状态、所属区域、实时缩略图、最近告警和详情入口。

告警点位按风险等级区分，支持聚合、时间过滤和事件详情打开。仅重大风险允许明显闪烁或呼吸动效。

---

# 9. 视频监控页规范

页面采用摄像头树、视频墙和 AI/事件侧栏三栏结构。

摄像头树支持项目、标段、区域、摄像头、在线状态、AI 状态、收藏、搜索和拖拽。

每个视频窗格显示摄像头名称、在线状态、延迟、码流、AI 开关、抓图、录像、全屏和更多操作。

窗格状态包括：加载中、播放中、暂停、断流、无权限、重连中、AI 异常。

AI 叠加层包含检测框、类别、置信度、区域边界、风险等级、跟踪 ID 和事件提示，并允许单独关闭。

视频墙支持单画面、2×2、4×4、双击放大、拖拽换位、保存布局和自动轮巡。

---

# 10. AI 中心规范

## 10.1 模型列表

字段包括模型名称、算法类别、版本、推理框架、状态、使用摄像头数、当前 FPS、最近发布时间和操作。

## 10.2 模型详情

按基本信息、模型文件、运行参数、绑定任务、性能指标、版本历史、推理日志和审计记录分区。

## 10.3 区域配置

视频截图作为背景，支持多边形区域绘制、区域命名、区域类型、屏蔽区域、删除顶点、撤销、重置和保存。

---

# 11. 告警中心规范

列表页由筛选条件、风险统计卡、告警表格、批量操作和分页组成。高风险事件应默认优先排序。

事件详情推荐采用三栏：左侧截图/录像，中部事件信息，右侧处置流程和操作记录。

事件操作根据状态动态显示确认、忽略、修改风险等级、创建工单、指派责任人、查看整改、导出事件和标记误报。

---

# 12. 整改中心规范

工单状态：待接单、整改中、待复核、已驳回、已销项、已逾期。

工单详情包括来源事件、整改要求、责任信息、截止时间、整改证据、整改说明、复核意见和操作时间线。

移动端 H5 以任务处理为主，支持查看任务、拍照、上传视频、填写说明、提交整改、查看驳回原因和再次提交。

---

# 13. 报表中心规范

报表列表字段包括报表名称、类型、项目、时间范围、生成人、生成方式、状态、创建时间和下载。

生成流程：选择报表类型、项目、时间范围、统计维度、预览、生成、下载。支持 PDF、Word 和 Excel。

---

# 14. Agent 助手规范

页面包括会话列表、对话区、输入框、快捷指令和工具调用卡片。

快捷指令建议提供：今日高风险事件、查询逾期整改、生成安全日报、查看离线摄像头、分析高风险区域、查询历史事件和生成巡查建议。

Agent 回答建议采用：结论、关键数据、风险说明、建议动作、数据来源和可执行操作。

工具调用过程应显示查询对象、调用结果、成功状态、耗时和是否需要确认。涉及写操作时，必须弹出确认卡片。

---

# 15. 系统管理规范

包含用户、角色、权限、企业、项目、字典、参数、审计日志、登录日志和消息模板。

管理页面统一采用左侧筛选、右侧表格、抽屉编辑和顶部批量操作。

---

# 16. 状态设计规范

所有页面必须覆盖：初始、加载、成功、空数据、局部错误、全局错误、无权限、网络断开、服务不可用和数据过期。

空状态应说明为空原因、下一步操作和创建入口。错误状态应包含错误原因、重试、返回、错误编号和联系管理员提示。

---

# 17. 响应式规范

## 17.1 桌面端

适配 1920×1080、2560×1440 和 3840×2160。

## 17.2 笔记本

适配 1440×900 和 1366×768。小屏幕下左侧导航折叠、右侧详情改抽屉、图表纵向堆叠、表格横向滚动。

## 17.3 移动端

移动端优先支持工单处理、告警查看、整改上传、消息通知和简化驾驶舱。首期不建议提供 4×4 视频墙、复杂 GIS 编辑、模型参数配置和大型报表编辑。

---

# 18. 可访问性规范

- 文本与背景保持足够对比度；
- 状态不只依赖颜色；
- 图标配 Tooltip；
- 表单错误有文字提示；
- 关键操作支持键盘访问；
- 视频控制按钮可聚焦；
- 图表提供替代说明；
- 动效可关闭。

---

# 19. 动效规范

允许页面淡入、抽屉滑入、数字轻量变化、风险点呼吸、骨架屏和状态切换动画。

禁止大面积炫光、复杂 3D 过场、高频闪烁、长时间自动滚动和影响判断的背景动画。

---

# 20. 页面验收标准

## 20.1 通用验收

- 页面结构与规范一致；
- 主要操作路径不超过 3 步；
- 高风险信息优先展示；
- 异步操作有反馈；
- 错误有明确提示；
- 写操作可追踪；
- 目标分辨率下无明显错位；
- 表格、弹窗、抽屉行为一致；
- 权限控制准确。

## 20.2 驾驶舱验收

KPI 实时更新，图表支持时间切换，指标可跳转，高风险数据突出，全屏模式正常，1920×1080 下无明显布局溢出。

## 20.3 GIS 验收

底图切换、图层开关、摄像头点位、告警点位、聚合显示和详情抽屉均正常。

## 20.4 视频页验收

单路、2×2、4×4 正常；抓图、录像、断流重连、AI 叠加层和双击放大正常。

## 20.5 告警与整改验收

状态切换准确，权限按钮准确，操作记录完整，整改前后证据可对比，逾期状态突出，复核通过和驳回流程完整。

## 20.6 Agent 验收

快捷指令可用，工具调用过程可见，回答包含数据来源，写操作需要确认，失败原因明确，历史会话可查询。

# 24. 总结

BridgeAI-Site 的 UI/UX 设计重点不是追求表面上的科技感，而是建立一个高效、可信、可追踪的工程管理工作台。

第一阶段必须优先保证：

1. 风险信息突出；
2. 视频和 GIS 操作流畅；
3. 告警与整改状态清晰；
4. Agent 调用过程透明；
5. 页面适合长期高频使用；
6. 所有关键操作可审计；
7. 产品可直接进入真实工地试点。

本规范完成后，BridgeAI-Site 已具备进入 Figma 高保真设计和前端组件拆分阶段的基础。

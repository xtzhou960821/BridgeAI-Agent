# BridgeAI-Agent V0.2 本地运行说明

本说明对应第一轮开发分支 `codex/v0.2-engineering-skeleton`，目标是验证工程骨架，而不是启动完整生产系统。

## 已验证命令

```bash
python -m pytest -v
```

该命令会验证当前纯 Python 核心：

- Tool SDK 注册、必填输入校验和执行结果；
- Workflow 状态推进、失败和恢复；
- Agent Runner 最小任务循环；
- 后端 Health payload。

## 后端启动

当前仓库未强制安装 FastAPI。安装后可启动后端入口：

```bash
set -a
source .env
set +a
python -m pip install -e ".[backend,dev]"
python -m uvicorn backend.app.main:app --reload --host 127.0.0.1 --port 8000
```

也可以直接让 Uvicorn 读取本地环境文件：

```bash
python -m uvicorn backend.app.main:app --env-file .env --reload --host 127.0.0.1 --port 8000
```

健康检查路径：

```text
GET /api/v1/health
```

执行 V0.2 示例巡检任务：

```bash
curl -s -X POST http://127.0.0.1:8000/api/v1/tasks/runs \
  -H "Content-Type: application/json" \
  -d '{
    "task_id": "task_001",
    "task_type": "bridge_inspection",
    "objective": "检查桥梁无人机影像质量",
    "artifact_ids": ["art_001"]
  }'
```

建议使用 `python -m uvicorn`，这样可以确保调用的是当前虚拟环境中的 Uvicorn，而不是 Anaconda 或系统环境中的全局命令。

## 前端启动

进入前端目录并安装依赖后启动：

```bash
cd frontend
npm install
npm run dev
```

当前前端为 V0.2 联调工作台，已接入健康检查和示例任务执行 API；持久化任务列表、Workflow 事件流、病害复核和报告能力将在后续迭代补齐。

## V0.2 联调验收

```bash
python -m pytest -v
cd frontend && npm run build
```

启动前后端后，在工作台刷新健康状态并执行示例任务。验收结果应同时包含模型 Profile、任务理解文本、usage、Workflow 历史和 Tool 输出。

## Agent Model Profile

当前默认 Agent Model Profile 为：

```text
model_id=DeepSeek-V4-Flash-4bit
model_version=omlx-current
alias=omlx-deepseek-v4-flash
provider=omlx
runtime=openai-compatible
api_base_url=https://omlx.cpolar.cn/v1
timeout_seconds=60
is_stub=false
```

任务理解阶段会通过 OpenAI-compatible Model Gateway 调用该模型，模型理解结果、模型 Profile 和 usage 会随 Workflow 返回。API key 使用本地 `.env` 的 `BRIDGEAI_AGENT_API_KEY`，不要写入仓库。

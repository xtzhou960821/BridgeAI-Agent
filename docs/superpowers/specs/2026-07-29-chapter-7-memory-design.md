# BridgeAI-Agent 第七章《Memory 与项目上下文设计》编制设计

## 1. 编制目标

在现有前六章的架构约束下，编制第七章《Memory 与项目上下文设计》V1.0，形成可指导 BridgeAI-Agent 第一阶段研发、联调和验收的正式工程设计文档。

本章聚焦桥梁与道路巡检 AI Agent，定义任务连续性、项目经验复用、用户与组织偏好、上下文压缩及记忆治理机制。内容应同时说明架构原则、数据契约、读写流程、权限边界、异常降级、评测指标和实施范围，但不替代后续章节的数据库物理设计、MCP 接入规范或 Prompt 模板设计。

## 2. 既有架构约束

第七章必须与前六章保持以下一致性：

- Agent 负责理解、规划和受策略约束的决策，Tool 负责专业能力执行。
- Workflow Runtime 以 LangGraph 为第一阶段核心编排运行时。
- LangGraph Checkpoint 保存线程执行快照，用于 Interrupt、恢复和历史调试，不承担长期项目记忆职责。
- PostgreSQL 业务表保存桥梁、道路、构件、病害、检测记录和人工复核结论等权威事实。
- RAG 提供规范、标准、指南、案例等可引用的外部工程依据；Memory 不复制或替代 RAG 知识。
- PostgreSQL 保存记忆元数据、结构化内容、权限、版本和审计记录；MinIO 保存长文本快照和大体积 Artifact；语义索引是可重建的检索派生物。
- Workflow State 只保存当前执行所需的有限上下文、记忆标识和摘要，不保存完整项目历史。
- 正式工程判断、病害等级、处治决策和报告签发必须保留人工复核。
- 系统坚持本地优先、最小权限、来源可追溯、模块可替换和全链路可审计。

## 3. 总体技术路线

采用“分层、可治理的 Memory 架构”，而不是单一结构化表或向量记忆优先架构。

选择该路线的原因如下：

1. 桥梁与道路巡检同时包含结构化项目事实、人工修订、任务摘要和报告偏好，单一存储形态不能覆盖全部需求。
2. 工程场景要求每条高风险记忆能够解释来源、确认状态、适用范围和失效条件，不能把相似度检索结果直接视为事实。
3. 第一阶段需要保持实现可控，向量召回只作为结构化过滤后的补充能力，不作为权威存储或自动决策依据。
4. 记忆服务必须与具体编排框架解耦，允许通过适配层使用 LangGraph Store，但业务语义、权限和生命周期不能绑定其内部实现。

## 4. Memory 定位与职责边界

Memory 定位为“面向任务连续性和项目复用的受控上下文服务”。

### 4.1 本章负责

- 任务记忆、项目记忆、用户与组织偏好、运行经验记忆的分类与作用域；
- 记忆来源、候选提取、校验、确认、发布、修订、失效和遗忘流程；
- 统一记忆对象、来源引用、权限、置信度、风险、版本和生命周期契约；
- PostgreSQL、MinIO、语义索引、LangGraph Store 和 Workflow State 的职责划分；
- 结构化过滤、语义召回、排序、去重、冲突检查和上下文组装；
- Context Builder 的 Token 预算、压缩、裁剪和上下文清单；
- Memory Service/Tool 的输入输出、权限、错误语义和审计要求；
- 与 Agent、Workflow、RAG、业务数据和人工复核的集成；
- 记忆污染、越权召回、提示注入、敏感信息和删除传播防护；
- 缓存、性能、降级、异常恢复、评测和第一阶段实施范围。

### 4.2 本章不负责

- 桥梁、道路、构件、病害和检测记录的业务主数据设计；
- 规范、标准和案例知识的采集、切分、索引、引用和证据治理；
- LangGraph Checkpointer 内部表结构及框架私有状态；
- 完整 PostgreSQL DDL、索引、迁移脚本和数据字典，由第八章负责；
- MCP Server、Resource 和 Tool 的互操作规范，由第九章负责；
- 通用 Prompt 模板、消息格式和结构化输出规范，由第十章负责；
- 前后端管理页面及生产部署的完整方案，由第十一章和第十三章负责。

## 5. 记忆分类与作用域

### 5.1 任务记忆

服务当前任务及其后续恢复或复盘，主要包括：

- 阶段摘要和任务目标变化；
- 用户修订及人工复核结论；
- 关键 Tool 结果、报告和 Artifact 引用；
- 已完成步骤、未决事项和降级原因；
- 当前任务专用术语和临时约束。

任务记忆不得复制完整 Checkpoint，只保存跨节点或跨线程仍有业务价值的摘要和引用。

### 5.2 项目记忆

服务同一桥梁、道路或巡检项目的跨任务复用，主要包括：

- 经确认的项目术语、构件别名和编码映射；
- 多期巡检之间的关联方式和历史处理经验；
- 项目采用的报告模板、交付规则和复核流程；
- 经人工确认的项目特殊约束；
- 对权威业务事实、报告和复核记录的稳定引用。

项目记忆只保存必要摘要和引用，不复制桥梁资产、构件、病害或检测记录。

### 5.3 用户与组织偏好

用于表达可撤销、可解释的交互与交付偏好，主要包括：

- 输出语言、单位制和术语习惯；
- 报告模板、图表形式和文件命名规则；
- 默认复核阈值和通知方式；
- 用户界面和工作流的非安全性默认选项。

偏好优先级为：当前任务明确指令高于项目配置，项目配置高于用户偏好，用户偏好高于组织默认值。系统安全策略、权限规则和强制复核要求不可被偏好覆盖。

### 5.4 运行经验记忆

用于保存经过评测或人工确认的系统运行经验，包括模型适用性、常见失败模式、Tool 组合经验和 Workflow 调整建议。运行经验只能影响候选排序、模型选择或风险提示，不得直接作为工程事实和规范依据。

第三章曾使用的“领域记忆”在本章中进一步收敛：规范、标准、病害知识和处治案例归入 RAG；可复用的模型经验、错误模式和标注经验归入受治理的运行经验记忆。

## 6. 总体架构与数据流

```text
Workflow 事件／Tool 结果／人工复核／用户明确操作／报告签发
                           ↓
                    Memory Event Collector
                           ↓
        候选提取 → 分类与作用域 → 去重 → 风险分级 → 来源绑定
                           ↓
                 规则校验／人工确认／隔离
                           ↓
          PostgreSQL 权威记录 + MinIO Artifact + 语义索引
                           ↓
        权限过滤 → 结构化检索／语义召回 → 排序 → 冲突检查
                           ↓
              Context Builder：预算、压缩、裁剪、清单
                           ↓
                Agent／Workflow／Tool 调用上下文
                           ↓
             使用反馈 → 更正／替代／失效／遗忘／评测
```

### 6.1 写入链路

1. 采集受支持的业务事件，不直接将全部会话或日志写入长期记忆。
2. 识别候选内容的类型、作用域、风险和敏感级别。
3. 绑定原始事件、业务记录、Tool 执行、人工复核或用户操作来源。
4. 执行格式检查、权限检查、去重、冲突检测和提示注入检测。
5. 低风险偏好可在用户明确操作后生效；任务摘要可经规则校验后生效；高风险项目事实必须由权威数据或人工确认支持。
6. 持久化权威记录和大体积 Artifact，并在事务提交后更新语义索引。
7. 发布记忆状态变化事件，供缓存失效、审计和评测使用。

### 6.2 读取链路

1. 依据组织、项目、用户、角色和敏感级别建立权限过滤条件。
2. 依据当前任务、Workflow 节点、资产、构件、病害类型和时间范围建立作用域条件。
3. 优先执行精确和结构化检索，按需补充语义召回。
4. 合并、去重并按相关度、新鲜度、可信度、确认状态和风险排序。
5. 排除失效、撤销、删除、越权、隔离和未确认的高风险候选记忆。
6. 检查记忆之间以及记忆与权威业务数据之间的冲突。
7. 由 Context Builder 在预算内生成上下文和 `context_manifest`。

### 6.3 反馈链路

每次记忆使用可记录接受、忽略、纠正、否定或举报。纠正生成新版本和替代关系，不原地覆盖历史；被人工否定的错误模式形成负向记录，防止同类内容再次自动写入。

## 7. 统一记忆对象

统一记忆对象至少包含以下字段组：

| 字段组 | 代表字段 | 目的 |
|---|---|---|
| 标识与类型 | `memory_id`、`memory_type`、`schema_version` | 唯一识别和兼容演进 |
| 作用域 | `scope_type`、`scope_id`、`project_id`、`organization_id` | 隔离任务、项目和组织 |
| 内容 | `content`、`summary`、`structured_facts` | 保存正文、摘要和结构化事实 |
| 来源 | `source_type`、`source_refs`、`evidence_refs` | 追溯原始事件和权威记录 |
| 质量与风险 | `confidence`、`risk_level`、`validation_status` | 控制是否可用和是否需要复核 |
| 权限 | `owner_id`、`visibility`、`allowed_roles`、`sensitivity` | 执行最小权限访问 |
| 生命周期 | `status`、`valid_from`、`valid_until`、`supersedes_id` | 管理发布、替代、失效和撤销 |
| 审计 | `created_by`、`created_at`、`updated_at`、`last_used_at` | 记录来源和使用历史 |
| 保留与删除 | `retention_policy`、`deletion_status`、`tombstone_at` | 实现保留规则和删除传播 |
| 检索派生 | `embedding_model_version`、`index_version` | 支持索引重建和回滚 |

状态流转至少支持：

```text
candidate → validating → active
    │            │          ├→ superseded
    │            │          ├→ expired
    │            │          ├→ revoked
    │            │          └→ quarantined
    │            └→ rejected
    └→ conflicted

revoked／expired／superseded／quarantined → tombstoned → deleted
```

`deleted` 表示内容及检索派生物已经按策略删除；为满足审计可保留不含原文的最小墓碑记录。

## 8. 存储与索引分工

- PostgreSQL：记忆对象、结构化内容、来源关联、权限、版本、状态、反馈、删除任务和审计事件的权威数据源。
- MinIO：长文本快照、会话归档、报告附件和其他不适合进入数据库的大体积上下文 Artifact。
- Qdrant 或等价语义索引：保存可重建的向量和最小过滤载荷；Memory 与 RAG 使用独立集合、独立权限过滤和独立生命周期。
- LangGraph Store：通过适配层提供框架内的命名空间访问，不承载不可替换的业务语义。
- LangGraph Checkpointer：只保存执行快照，不被 Memory Service 修改或当作长期检索库。
- Workflow State：只保存本次召回的 `memory_id`、必要摘要、上下文版本和 `context_manifest_id`。

完整表结构、索引、外键、分区和迁移方案在第八章展开。本章正文提供概念模型、关键字段和 Pydantic 契约，不提供完整 DDL。

## 9. Context Builder 设计

Context Builder 采用预算制上下文组装：

1. 固定保留系统规则、安全边界、当前任务目标和权限上下文。
2. 加入当前 Workflow 节点必需的状态及 Tool 契约。
3. 优先召回同项目、同资产、同构件、同病害类型的已确认记忆。
4. 依据节点类型分配任务记忆、项目记忆、偏好和运行经验的 Token 配额。
5. 对重复历史采用分层摘要，保留关键修订、人工结论、时间范围和来源引用。
6. 超出预算时优先裁剪低价值运行记录、过旧候选和重复摘要，不压缩安全规则、人工复核结论和权威来源引用。
7. 生成 `context_manifest`，记录使用的记忆版本、来源、排序分数、裁剪项、压缩方法和上下文哈希。

上下文压缩不得引入原始来源不存在的新事实。高风险摘要在进入长期项目记忆前必须通过关键字段比对或人工复核。

## 10. 治理、安全与隐私

### 10.1 写入治理

- 自动提取内容默认进入候选状态，不默认成为长期有效记忆。
- 项目事实必须关联业务数据主键、人工复核记录或签发报告。
- 病害等级、处治建议、构件状态和报告签发结论不得仅凭模型摘要写入。
- 规范条款和行业知识不写入 Memory，继续由 RAG 提供版本化证据。
- 记忆版本不可原地覆盖，修订通过新版本、替代关系和审计事件表达。

### 10.2 权限与隔离

- 先执行组织、项目、用户、角色和敏感级别过滤，再进行语义召回。
- 默认禁止跨项目共享；跨项目经验必须经过脱敏、审批和组织级发布。
- 向量载荷、缓存键、对象存储路径和上下文快照必须包含租户及项目隔离信息。
- Prompt、日志和追踪数据只能包含调用者有权访问的内容。
- 权限撤销和删除必须传播到缓存、语义索引、派生摘要和未完成任务。

### 10.3 污染与冲突

- 外部文本、会话内容和模型输出均按不可信输入处理。
- 疑似提示注入、来源缺失、置信度过低或越权内容进入隔离区。
- 新旧记忆冲突时不自动覆盖；优先采用权威业务事实和最新人工确认，并向 Agent 暴露冲突标记。
- Agent 不得自行裁决工程责任相关冲突。
- 人工否定的错误记忆形成负向记录和回归样例。

### 10.4 用户权利与保留

在授权范围内支持查看、更正、撤销和删除。记忆保留策略依据类型、项目状态、合同要求和安全级别确定；项目结束不等于立即删除，但必须停止默认召回并进入归档或保留评估。

## 11. 异常、降级与恢复

- Memory 服务不可用时，主流程退化为当前 Workflow State、权威业务数据和 RAG，不阻断已经完成的专业 Tool 结果落库。
- 语义索引失败时退化为 PostgreSQL 结构化检索。
- 摘要生成失败时保留原始引用，不写入不完整记忆。
- 权限判断异常时默认拒绝召回。
- 写入失败生成可重放的补偿任务，并记录失败阶段、幂等键和告警。
- PostgreSQL 写入成功而索引更新失败时，以 PostgreSQL 状态为准，通过 Outbox 或等价机制重建索引。
- 删除传播失败时，目标记忆立即进入不可召回状态，并持续执行缓存、索引和 Artifact 清理。
- 所有召回、写入、确认、修订、失效、撤销和删除操作形成审计事件。

## 12. Memory Service 与集成边界

第七章正文应定义以下核心能力：

- `memory.propose`：提交候选记忆；
- `memory.confirm`：确认候选或高风险记忆；
- `memory.search`：按权限和作用域检索；
- `memory.feedback`：记录接受、忽略、纠正或否定；
- `memory.correct`：创建修订版本并建立替代关系；
- `memory.revoke`：立即停止记忆召回；
- `memory.forget`：启动删除和派生物清理；
- `context.build`：由受控服务调用，组装节点上下文和清单。

可由 Agent 调用的写操作必须经过 Policy Engine 和权限校验。`context.build`、高风险确认、跨项目发布和删除传播不作为任意模型可自由调用的能力。

### 12.1 与 Workflow 集成

Workflow 在关键节点产生记忆候选事件，在任务完成、人工复核完成、报告签发和项目归档时触发汇总或生命周期操作。Checkpoint 恢复不自动生成长期记忆，避免重复和污染。

### 12.2 与 Agent 集成

Context Builder 在 Agent 推理前按节点构造上下文。Agent 获取的是受权限和预算控制的上下文包，不直接访问记忆数据库或向量索引。

### 12.3 与 RAG 集成

RAG Evidence Pack 可作为记忆来源引用，但 Memory 只保存必要摘要、查询标识和证据引用。需要工程依据时必须重新按权限和版本状态读取 RAG 证据，不把旧摘要当作有效规范条款。

### 12.4 与业务数据集成

业务表是资产、构件、病害和检测结果的事实源。Memory 通过稳定 ID 引用业务记录；当业务事实修订时，相关记忆进入重新校验或失效流程。

## 13. 目标应用场景

第一阶段围绕以下桥梁与道路巡检场景设计：

1. 同一桥梁多期巡检时复用构件别名、拍摄区域、历史修订和报告规则。
2. 任务中断或跨班组交接时，以受控摘要继续处理，不依赖完整会话回放。
3. 人工纠正病害识别、构件定位或报告表达后，在同项目后续任务中复用确认结果。
4. 根据项目、组织和用户层级继承报告模板、单位制、术语和复核流程。
5. 记录模型与设备在特定环境下的已验证适用性和失败模式，辅助 Tool 路由和风险提示。
6. 在项目归档、权限撤销或用户删除请求后，停止召回并清理派生内容。

## 14. 评测与验收指标

第一阶段至少建立以下评测维度：

| 类别 | 首期验收要求 |
|---|---|
| 权限隔离 | 固定越权测试集中跨组织、跨项目未授权召回数量为 0 |
| 高风险写入 | 无权威来源或人工确认的高风险事实进入 `active` 的数量为 0 |
| 删除正确性 | 已撤销、删除或超过有效期的记忆再次召回数量为 0 |
| 来源可追溯 | 进入上下文的项目事实具备可解析来源引用的比例为 100% |
| 摘要忠实度 | 人工标注评测集中关键事实、否定关系、数值、单位和时间的保真率不低于 98% |
| 召回覆盖 | 标准项目评测集中的已确认目标记忆 Recall@10 不低于 90% |
| 冲突处理 | 固定冲突用例中自动覆盖权威事实的数量为 0，冲突标记召回率为 100% |
| 降级能力 | Memory 或语义索引故障时，主巡检 Workflow 按预设路径完成或进入人工复核 |
| 性能 | 20 个并发会话下，不含模型生成的记忆检索与上下文组装 P95 不高于 1.5 秒 |
| 审计完整性 | 写入、读取、确认、修订、撤销和删除操作的审计事件覆盖率为 100% |

测试体系应覆盖单元测试、契约测试、集成测试、权限负向测试、提示注入测试、故障注入、删除传播测试、摘要回归和真实项目验收。

## 15. 第一阶段实施范围

### 15.1 必须交付

- 任务记忆、项目记忆、用户与组织偏好三类核心记忆；
- 候选提取、确认、版本替代、失效、撤销和删除闭环；
- PostgreSQL 权威存储、MinIO Artifact 管理和可重建语义索引；
- Memory Service/Tool 的写入、召回、反馈、修订和遗忘契约；
- Context Builder 的预算、排序、压缩、裁剪和 `context_manifest`；
- Agent、Workflow、RAG、业务数据和人工复核集成；
- 权限、审计、降级、补偿、评测和真实巡检案例验收。

### 15.2 首期不纳入

- 无审批的跨项目记忆共享；
- 完全自动的长期经验学习；
- 多 Agent 之间自由共享记忆；
- 用 Memory 替代业务主数据或 RAG 知识库；
- 由记忆直接触发设备控制、正式评定、处治决策或报告签发；
- 与第一阶段交付无关的通用记忆市场或复杂知识图谱。

### 15.3 里程碑

1. 契约与权威存储：完成记忆对象、状态机、作用域、权限和 PostgreSQL 概念模型。
2. 写入治理：完成事件采集、候选提取、确认、版本、隔离和审计链路。
3. 检索与上下文：完成结构化检索、语义召回、排序、压缩和清单。
4. 系统集成：打通 Agent、Workflow、RAG、业务数据、人工复核和异常降级。
5. 评测与验收：以多期桥梁巡检、人工修订复用和项目归档为真实案例完成验收。
